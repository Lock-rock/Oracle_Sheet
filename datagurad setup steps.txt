Notes: The DB_NAME parameter for the standby database should match that of the primary database, but it needs a distinct DB_UNIQUE_NAME. In this example, we’ll set the standby database’s DB_UNIQUE_NAME to "cdb1_stby".

To configure the primary database for DataGuard, set the necessary initialization parameters. These configurations facilitate data transfer between primary and standby databases.


-- Set DataGuard configuration parameters
    ALTER SYSTEM SET log_archive_config='DG_CONFIG=(cdb1,cdb1_stby)' SCOPE=BOTH;
    ALTER SYSTEM SET log_archive_dest_1='LOCATION=/oracle/arch VALID_FOR=(ALL_LOGFILES,ALL_ROLES) DB_UNIQUE_NAME=cdb1' SCOPE=BOTH;
    ALTER SYSTEM SET log_archive_dest_2='SERVICE=cdb1_stby LGWR ASYNC VALID_FOR=(ONLINE_LOGFILES,PRIMARY_ROLE) DB_UNIQUE_NAME=cdb1_stby' SCOPE=BOTH;
    ALTER SYSTEM SET log_archive_format='%t_%s_%r.arc' SCOPE=SPFILE;
    ALTER SYSTEM SET fal_server='cdb1_stby' SCOPE=BOTH;
    ALTER SYSTEM SET fal_client='cdb1' SCOPE=BOTH;
    ALTER SYSTEM SET standby_file_management='AUTO' SCOPE=BOTH;
	
	
Now add standby Redo logs(SRLs):Creating Standby Redo Logs on the Primary Database
To prepare for smooth role transitions, such as switchovers, it’s essential to create standby redo logs on the primary database. These logs should match or exceed the size of the largest online redo logs, with an additional group created per thread. This redundancy helps ensure data is captured even during role changes. The following example demonstrates how to set up standby redo logs on both primary and standby servers:


For check SRLs on primary database:

FOR RMAN 0:

cat RMAN_LEVEL0.sh
#!/bin/sh

export ORACLE_SID=PEGAPRD
export ORACLE_HOME=/u01/app/oracle/product/19.0.0/dbhome_1
export PATH=${PATH}:${ORACLE_HOME}/bin
export TODAY=`date +"%d_%b_%y"`
$ORACLE_HOME/bin/rman target / log='/backup/logs/PEGAPRD/LEVEL_0_OUTPUT.log' append << EOF
run {
allocate channel ch1 device type disk;
allocate channel ch2 device type disk;
allocate channel ch3 device type disk;

crosscheck archivelog all;
delete noprompt expired archivelog all;
crosscheck backup of database;
delete noprompt expired backup of database;
backup format '/backup/rman/PEGAPRD/full/LEVEL_0_%d_%T_%s_%p_%u.ctl' current controlfile;
backup as backupset full database tag='FULL_BKP' format '/backup/rman/PEGAPRD/full/LEVEL_0_%d_%T_%p_%U.dbf' (database);
backup as backupset tag='PEGADB_ARCH' ARCHIVELOG ALL NOT BACKED UP 1 TIMES FORMAT '/backup/rman/PEGAPRD/full/arch_%d_%T_%p_%U.arc';
backup spfile format '/backup/rman/PEGAPRD/full/spfile_%d_%T.ora';
backup format '/backup/rman/PEGAPRD/full/LEVEL_0_%d_%T_%s_%p_%u.ctl' current controlfile;
release channel ch1;
release channel ch2;
release channel ch3;

}
EOF

Check Data Guard Error Messages (Hidden but Powerful)

Run on BOTH SERVERS

SELECT message_num,
       severity,
       message
FROM v$dataguard_status
WHERE severity IN ('Error','Fatal')
ORDER BY timestamp DESC;


For checking alter logs:
SELECT value FROM v$diag_info WHERE name = 'Diag Trace';

ONE-COMMAND QUICK ERROR CHECK (Best for Interviews)
Run on BOTH SERVERS

SELECT 'ARCHIVE_DEST' source, error
FROM v$archive_dest
WHERE error IS NOT NULL
UNION ALL
SELECT 'DG_STATUS', message
FROM v$dataguard_status
WHERE severity IN ('Error','Fatal');
